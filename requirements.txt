1. PROJECT OVERVIEW
System Name: College Course Allotment Portal
Purpose: Comprehensive platform for students to express course preferences and receive allotments, with admin controls for course and student management
Users: Students, Administrators
Tech Stack: Node.js/Express (Backend), React with Vite (Frontend), MySQL (Database), TypeScript (Language)
Scope: DBMS Lab Project - Full-stack implementation with preference-based course allotment system



2. SYSTEM ENTITIES
2.1 DEPARTMENT
Department_ID (Primary Key, Auto-increment)
Department_Name (Unique)

2.2 STUDENT
Roll_No (Primary Key, String)
Name
Email (Unique)
Password (Hashed with bcrypt)
Department_ID (Foreign Key -> DEPARTMENT)
Semester
CGPA
Status (ENUM: active, inactive, graduated, suspended)

2.3 COURSE
Course_ID (Primary Key, String)
Course_Name
Credits
Department_ID (Foreign Key -> DEPARTMENT)
Semester
Status (ENUM: active, inactive, archived)
Capacity
Slot
Faculty
Course_Type (ENUM: core, elective)
Elective_Slot
Max_Choices

2.4 ADMIN
Admin_ID (Primary Key, Auto-increment)
Name
Email (Unique)
Password (Hashed with bcrypt)

2.5 PREFERENCE (Student course preferences before allotment)
Student_Roll_No (Foreign Key -> STUDENT)
Course_Course_ID (Foreign Key -> COURSE)
Rank (Priority/Choice number)
Primary Key: (Student_Roll_No, Course_Course_ID)

2.6 ENROLLMENT (Allotment results)
Student_Roll_No (Foreign Key -> STUDENT)
Course_Course_ID (Foreign Key -> COURSE)
Enrollment_Date
Grade
Status (ENUM: allotted, waitlisted)
Primary Key: (Student_Roll_No, Course_Course_ID)

2.7 ADM_IN_ACCESS (Admin-Course relationship)
Admin_ID (Foreign Key -> ADMIN)
Course_ID (Foreign Key -> COURSE)
Primary Key: (Admin_ID, Course_ID)



3. FUNCTIONAL REQUIREMENTS
3.1 STUDENT FUNCTIONS
Register using college email ID
Login after account creation (no admin approval required)
View available courses with filters:
  Department
  Semester
  Course status (Active only)
  Course type (Core/Elective)
Submit course preferences with rankings
View submitted preferences before allotment
View allotment results (Allotted/Waitlisted status)
View enrolled courses with grades
Cannot duplicate preferences for the same course
Account status management (active/inactive/graduated/suspended)

3.2 ADMIN FUNCTIONS
Login to system
Add new courses with all details
Update existing course information
Activate, deactivate, or archive courses
Delete courses
View list of all registered students
View and update student status (active/inactive/graduated/suspended)
Trigger course allotment process
View allothashed using bcrypt algorithm
JWT-based authentication and authorization
Only authenticated users can access the system
Role-based access control (Student vs Admin)
Students cannot access admin functionalities
Secure API endpoints with middleware protection



4. NON FUNCTIONAL REQUIREMENTS
4.1 Performance Requirements
System should handle concurrent student logins and preference submissions
Course listing should load within acceptable response time
Preference submission should be atomic and consistent
Allotment process should complete efficiently for large datasets

4.2 Data Integrity Requirements
Duplicate student registration using same email prevented at database level
Unique email constraint enforced for both students and admins
A student cannot duplicate preferences for the same course
Only active courses available for preference submission
Referential integrity maintained through foreign keys
Cascading deletes for course data

4.3 Usability Requirements
Intuitive user interface for both students and admins
Clear navigation between different sections
Real-time feedback for form submissions
Visual indication of preference rankings
Clear status displays (allotted vs waitlisted)
Responsive design for multiple screen sizes

4.4 Reliability Requirements
Database transactions for preference and allotment operations
Proper error handling and validation
